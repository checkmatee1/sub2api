# Copilot 上游接入实施计划

> 执行方式：本会话逐项实施，使用 executing-plans；按用户指令不新增单元测试，全部实现完成后集中运行完整测试套件。

**目标：** 在 fork 中交付可追溯的 Copilot 适配集成，并保持现有中转站连续运行。

**架构：** 独立适配服务提供 OpenAI/Anthropic 兼容接口；通过带认证的本地入口连接 Sub2API。复用现有自定义上游能力，优先避免修改核心路由。

**技术：** Sub2API、Docker Compose、经审查并锁定版本的适配器、独立认证网关、部署和验证脚本。

**设计：** copilot-sub2api-design.md（已确认）。

## 全局约束

- 开发目录：Mac mini /Users/checkmate/Documents/sub2api-copilot。
- 绝不停止、重启、重建 sub2api-snapshot，不修改其 runtime/、数据库和现有账号。
- 新配置字段先记录于独立 .env.example；秘密由本机程序生成或设备授权流程取得，不输出令牌。
- 开发分支从核实后的 main 历史创建，保留 Conventional Commit 提交。
- 新服务独立网络、端口、存储和资源限制；不用线上数据库执行迁移。

## 审查重点

- 未认证请求必须被拒绝，认证信息不能记录到日志。
- 流式、工具调用、错误状态、取消必须保留协议语义。
- 适配器登录及令牌续期不能泄露凭证。
- 现有线上容器启动时间、重启次数及健康状态保持基线。
- Docker 容器访问宿主机入口需要明确 host.docker.internal 与安全接入方式。
