# Copilot Responses 接口设计与实施计划

目标：使已验证上游可用的 GPT-5.4 nano 能经 Sub2API 使用原生 Responses 协议。

方案：在现有固定版本的 Bun/Hono 适配器中添加 POST /responses 与 /v1/responses。复用 Copilot 服务令牌和固定上游地址、限流及错误脱敏；JSON 和 SSE 原样转发，向上游传递客户端取消。相比新增另一套代理，复用现有机制可减少凭证和运维入口；相比协议转换，原生转发保留 Responses 语义。

约束：原 sub2api-snapshot 不停止、不重启。复用已隔离开发副本及 feat/copilot-upstream 分支。现有 Copilot 实例继续运行；新版本在独立项目和端口部署，验证后才调整专用账号。所有生成凭证仅由执行机器上的程序读取和使用。

遵照用户测试规则：实现期间不创建、不运行单元测试；实现完成后统一运行完整适配器套件，并进行真实接口集成验证。本次不修改 Sub2API 主应用源码。

## 验收和回滚

验收：GPT-5.4 nano 非流式得到有效 output，流式得到完成事件；工具定义及调用 ID 保留；上游错误无凭证；原模型可用；原服务启动时间、重启次数保持不变。

回滚：暂停新增 Responses 专用账号；旧 Chat 账号和旧端口仍可使用。候选实例独立可撤销，不涉及停止主服务。

## 实际结果与边界

26 项完整适配器测试、类型检查和 11 项 HTTP 集成检查通过。真实候选实例及线上 Sub2API 的 JSON、SSE 和工具调用全部返回 200。账号 6 使用 copilot-gpt-5.4-nano，位于专属分组 7；本次未执行任何模型请求中的外部工具。

回归检查发现旧账号 5 在 2026-11-10 09:22:55 UTC 已暂停调度，早于新账号创建（12:28:41 UTC）。其原三个模型直接经旧适配器均返回 200；不为满足回归测试而擅自改变已有暂停状态。主服务无需修改。

独立审查指出视觉输入需带 Copilot 视觉标记，已补齐并验证头部；没有进行真实图像推理验证。取消传播在独立本地 HTTP 集成检查中通过；不据此断言 Sub2API 主服务在客户端断连后停止其上游计费读取。
